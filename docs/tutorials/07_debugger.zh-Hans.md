# 第 7 课：用调试器看看处理器内部

你的游戏是一串 RISC-V 指令。处理器一条一条地运行它们，速度非常快：每一帧都要运行几万条。
**调试器** 能让它停下来，一次只运行一条指令，让你看到真正发生了什么。

你需要一个由本工具构建的卡带：在 IDE 中按 **运行**，然后打开编辑器下方的 **调试** 标签页；或者按
**编译**，再点击顶部菜单中的 **调试**（带调试器的播放器，调试器在屏幕下方）。在那个页面上你也可以
打开任意 `.prg32` 文件。

## 给学生

1. 打开 **调试模式**。现在处理器在每条指令之前都会检查你是否让它在那里停下。
2. 按 **单步**。蓝色的一行是下一条指令；每走一步它就往下移。看看 **寄存器**：刚刚改变的那个会变成黄色。
3. 点击某个地址左边的灰色区域。会出现一个红色的 **●**：这就是 **断点**。按 **继续**：游戏会运行，
   并正好在那条指令之前停下。再按一次 **继续**：它再运行一帧，然后又在那里停下。
4. **单步执行一帧** 会运行到这一帧的末尾（update + draw）然后停下，除非先遇到断点。
5. 把速度设为 **0.01×** 并按 **继续**：你能看到蓝色的一行在代码中慢慢走动。

可以留意的地方：

- **Update** 和 **Draw** 按钮显示你的 `update` 和 `draw` 函数从哪里开始。每一帧处理器先运行 update，
  再运行 draw。
- `a0` 保存函数收到的第一个数，也保存函数返回的数。在一个 `jalr`（函数调用）之后放一个断点，看看 `a0`。
- `sp`（栈指针）在函数开始时会 *下降*（`addi sp, sp, -16`），在函数结束时会 *回升*。
- **游戏时间** 是游戏认为已经过去的时间（每帧 33 毫秒）。**实际时间** 是你的时钟。在 0.01× 时两者
  差别很大，但游戏的行为完全一样。

## 调试你的积木、C 或汇编

如果卡带是由本工具构建的（在 IDE 中按 **运行**，或者按 **编译** 后点击顶部菜单中的 **调试**），调试器
还认识你的程序，而不只是它的指令。在机器码下面你会看到：

- **积木**（积木项目）：你的积木。游戏停下时，正在运行的积木会有蓝色边框。点击一个积木（或在列表中
  选择它），然后按 **● 积木断点**：每次这个积木开始运行时，游戏都会停下。
- **game.c** 或 **game.S**：你的源代码。正在运行的一行是蓝色的。点击一个行号，就能在那一行放一个
  **●** 断点。如果某一行本身没有代码（编译器把它的工作移走了），断点会放到下一个有代码的行，播放器
  会告诉你。
- **下一个积木** / **下一行**：运行到程序中的下一个积木（或下一行）。函数调用会整个运行完。
- **变量**：你的积木变量（`score`、`ball_x`……）及它们的值。在高级视图中还有正在运行的函数的变量。
- **监视**：输入一个名字并按 **监视**：`score`、`player.x`、`heights[2]`，或者 `a0` 这样的寄存器。
- **调用栈**：哪个函数调用了哪个函数。点击其中一个可以看到它的变量。
- **只在……时停下**：给断点一个条件，例如 `score > 10`，游戏只会在条件成立时在那里停下。

试一试：在移动球的积木上放一个断点，监视 `ball_x`，然后按几次 **继续**。给断点加上条件 `ball_x < 50`：
现在它只会在球靠近左墙时停下。

有时一个变量会显示 *被优化掉了*：编译器让你的程序跑得更快，在这个位置没有保留那个值。调试器会这样
告诉你，而不是去猜。

有时调用栈会显示一个标记为 **内联到** 另一个函数的函数：编译器把这个小函数复制到了调用它的函数里，
所以它没有自己的帧。调试器仍然会显示你在它里面的位置，以及调用它的那一行；但不会显示它的变量
（点击它被内联到的那个函数，就能看到那个函数的变量）。

**你的断点会保留下来**，即使你修改游戏并重新编译。每个断点都记得它那一行的代码：如果代码移动了，
断点也会跟着移动；如果代码没有了，断点会被列为 *代码已经改变*，不会被放到别的地方。断点前面的复选框
可以关闭断点而不丢失它（它在源代码中的圆点会变成 ○）。

## 高级视图

**高级** 会用十六进制显示全部 32 个寄存器、每条指令的机器字、一个内存查看器，还有两个额外的按钮：

- **单步跳过**：遇到调用（`jal`、`jalr`）时，把被调用的函数整个运行完，并在下一行停下。
- **单步跳出**：一直运行，直到当前函数返回到调用它的地方。

内存查看器接受十进制地址（`1082130432`）或十六进制地址（`0x40800000`），最多显示 1024 个字节的
十六进制和文本。对于本工具构建的卡带，高级视图还会显示 **计数器 CSR**（`cycle`、`time`、`instret`：
也就是 `csrr` 会读到的值）和 **栈**：`sp` 周围的字。

入门和高级是查看同一件事的两种方式：切换视图不会改变游戏，断点也会保留。

## 给老师

- 它和 PRG32-QT 的调试器相同（同样的指令，同样的规则：在指令运行之前检查断点；**继续** 会离开当前
  断点一次）。单步跳过、单步跳出、单步执行一帧和入门视图是新增的功能；参见 `../compatibility.md`。
- 断点会针对那个确切的卡带保存在浏览器中。重新编译的卡带是另一个卡带，开始时没有断点。
- 一切都在学生的浏览器中运行；不会向服务器发送任何内容。
- 适合入门的练习：数一数一帧需要多少条指令（在同一个断点的两次停下之间观察指令计数器）；找出改变
  精灵 x 坐标的那条指令；把一个积木游戏和它生成的汇编对比一下（编辑器中的 **生成**）。
- 源代码和积木调试需要由本工具编译的卡带：本工具在编译时会另外生成调试信息（卡带本身完全一样，
  `../adr/0015-source-and-block-debugger.md`）。从文件打开的 `.prg32` 只有机器码调试器。
- 一个关于积木的好练习：用条件为 `score > 0` 的断点，找出是哪个积木改变了 `score`。
